# 晋升文化与抗自欺：让"变好"可信、可累积、可回放

> 优化的真正敌人不是"改不动"，而是"以为自己改好了"。
> 这篇讲 self-optimize-agent 为什么坚持"显著才晋升"、为什么写实验账本、以及如何把自我改进变成一种机制而非一时冲动。

---

## 一、晋升门槛为什么不能省

### 1.1 "感觉变好"是最便宜也最贵的错误

没有对照时，人（和模型）会：
- 只记得成功的几例，忘记失败的多数（可用性偏差）。
- 把"不同样本"的差异当成"改动"的差异（混淆变量）。
- 一旦"变好"的叙事成立，后续证据会被选择性忽视（确认偏误）。

晋升门槛（显著性 + 最小样本 + 无回归）就是**用机制对抗这些认知偏误**。它不问"你感觉如何"，只问"数据是否站得住"。

### 1.2 晋升 = 承诺，不是建议

一旦 candidate 晋升为 baseline：
- 它成为后续所有实验的**对照锚点**。
- 未来的候选都要在它之上证明自己。
- 错误晋升会污染所有后续比较（基线本身就烂）。

所以晋升必须保守。本 Agent 宁可"未证实也不晋升"，也不放一个没把握的基线进去。

---

## 二、实验账本：把学习变成零负担

### 2.1 账本是什么

`experiment_log.jsonl` 是追加式日志，每行一条事件：
- `define`：本次实验的配置（指标/方向/基线/候选）。
- `sample`：一对对照得分。
- `promote`：晋升事件（含提升量、p 值）。
- `rollback`：被拒候选 + 原因。

### 2.2 账本的三个价值

1. **可回放**：任何结论都能追到原始样本，不接受"我记得当时更好"。
2. **可累积**：历史实验喂给 `bayes.py`，指导下一个候选（EI 需要知道"哪些点试过了、得分多少"）。
3. **可审计**：别人（或未来的你）能看懂"为什么这个 baseline 是这样"，而非黑盒。

> 这直接回应 4.7 评价的那句"校准功能需要你主动记录'我以为/实际'，有使用门槛"——本 Agent 把"主动记录"做成**自动账本**，门槛降到 0。

### 2.3 与 self-improvement 的棘轮同源

self-improvement-agent 的"错→永久记忆→升指令→抽 skill"是**错误棘轮**：坏的东西不再重复。
本 Agent 的实验账本是**改进棘轮**：好的候选一旦显著胜出，就钉进 baseline，不再回退。
两者共同构成"自我"的可持续进化——一个防退步，一个促进步。

---

## 三、避免"自以为变好"的四道防线

| 防线 | 机制 | 破防后果 |
|---|---|---|
| 对照 | baseline 锁死，只动 candidate | 回归盲区 |
| 显著 | Welch t + α，未达不晋升 | 随机波动被当提升 |
| 无回归 | 次指标不恶化 | 单点涨、整体塌 |
| 账本 | 全事件可追 | 记忆偏差、不可审计 |

任何一道撤掉，优化都会退化成"自我安慰"。

---

## 四、晋升之后：递归改进

晋升不是终点，是新起点：
- 新 baseline 成为下一轮 define 的基线。
- `suggest`（bayes.py 的 EI）基于含新晋升点的历史，推荐下一个更值试的配置。
- 这实现 RISE（NeurIPS 2024）的"递归自我改进"：每轮都从当前最佳出发，检测并改正上一轮不足。

**关键纪律**：晋升后不要"清零重来"。历史（尤其是被拒候选）是宝贵财产——它告诉你"哪些方向走过、不通"。

---

## 五、何时停止、何时扩大空间

- **停止**：达预算上限、连续被拒、EI 趋零。停止时报告当前最佳，这是对成本诚实。
- **扩大空间**：若连续被拒且 EI 仍高，说明旋钮范围太窄（好配置在界外），应放宽 optim_space 的 range 或加新 knob。
- **换方向**：若主指标长期卡住，可能问题不在"调参"而在"架构/流程"，该回到 self-debug 或 self-evaluate 重新审视，而非在错误层面死调。

---

## 六、给使用者的心态建议

1. **把每次改动当假设**：candidate 是"我猜这样更好"的假设，实验是验证，不是证明。
2. **拥抱被拒**：rollback 不是失败，是"帮我省下了一个坏基线"。账本里的被拒记录价值不输晋升。
3. **小步快跑**：与其一次大改赌一把，不如多次小改、每次都能晋升一点点。贝叶斯优化本就靠"小步 + 数据"逼近最优。
4. **尊重成本**：optimize 的"评估"贵，别为 0.01 分的提升耗尽 20 轮预算。看 diff 也看 p。

---

## 七、与同系列的协作边界

- 分数来源：self-evaluate（Reflexion 多轮）与 self-verify（门禁）提供"目标函数"与"下限保障"。
- 不要本 Agent 自己发明分数——那会破坏"受控"的前提。上游没评估，先去 evaluate。
- optimize 的产物（晋升的 baseline）应回流到 self-improvement 的永久记忆，完成"评估→优化→固化"的大闭环。

---

## 八、一句话总结

> **自我优化的诚实，不在于"我改了多少"，而在于"我能不能证明改对了"。**
> 显著才晋升、全量入账本、递归再出发——这就是 self-optimize 的晋升文化。

# 受控实验方法：A/B、显著性与回归护栏

> 优化失败，十有八九不是"没改好"，而是"没对照、没显著性、没护栏"。
> 这篇讲清楚 self-optimize-agent 怎么把一次"自以为变好"升级成"数据证明变好"。

---

## 一、为什么必须是受控实验

直觉式优化常犯两个错，本 Agent 用机制硬抗：

### 1.1 回归盲区

你改 A，以为整体变好，却悄悄把 B 弄坏了。没有对照基线，你无从得知。
**机制**：每次实验只动 candidate，baseline 锁死。基线和候选打**同一组样本**，差异才可归因到"改动"而非"样本差异"。

### 1.2 自欺盲区

人（和模型）天然会"确认自己变好了"。一句"感觉更顺了"就能骗过自己。
**机制**：差异必须过统计显著性（Welch t 检验 + 预设 α）。未达标的提升只能记作"未证实"，不能写进结论。

---

## 二、A/B 实验的正确姿势

### 2.1 定义阶段（--define）

锁定四件事：
1. **指标（metric）**：要优化的分数，通常来自 self-evaluate 的总分或某维度。
2. **方向（direction）**：higher（越大越好）或 lower（越小越好）。
3. **基线（baseline）**：当前已知最佳配置/提示/流程，不可在实验中改动。
4. **候选（candidate）**：本次只改这一处。

> 铁律：**一次只改一个变量**。同时改 prompt_style 和温度，你无法判断哪个贡献了提升。多变量改动请拆成多次实验或用 optim_space 的多旋钮正交设计。

### 2.2 累积样本（--run）

对**同一批受试样本**，分别用 baseline 和 candidate 产出并打分，得到一对 (b, c)。
- 一次可喂一批（--n），但每对必须"同一受试样本"。
- 样本量建议 ≥ 最小样本（默认 8 对）。太少时 compare 会拒绝判定（避免自欺）。

### 2.3 比较（--compare）

计算：基线均分 mb、候选均分 mc、差异 diff = mc − mb。
用 **Welch t 检验**（两样本方差可能不等）：
- t = (mc − mb) / sqrt(vb/nb + vc/nc)
- 近似双侧 p = 2·(1 − Φ(|t|))

判定：
- 方向对（higher 时 diff>0；lower 时 diff<0）**且** p < α → **显著胜出**，可晋升。
- 方向不对 → 不晋升，候选应丢弃。
- 方向对但 p ≥ α → "未证实"，继续累积样本或换候选，**不晋升**。

> 实现用正态近似 p 值（样本小会偏保守），作为门槛足够。若你要更精确，可换 t 分布。

### 2.4 晋升或回滚（--promote / --rollback）

- 通过 → 候选晋升为新 baseline，记录 promotion 事件（含提升量、p 值）。
- 不通过 → 显式 rollback，baseline 不动。日志里留下"被拒候选 + 原因"，供未来参考。

## 三、统计显著性的分寸

### 3.1 为什么需要最小样本

2 对样本算出的 p 值毫无意义——随机波动就能制造"显著差异"。本 Agent 默认 `min_samples=8`，未达则不判定。这不是限制，是保护。

### 3.2 α 的取值

- 默认 α = 0.05：传统显著性门槛。
- 实验代价高、试错成本大时，可调严（α = 0.01）避免假阳性晋升。
- 实验代价低、想多探索时，可调宽（α = 0.10）——但记得：放宽是双刃剑，放宽是假阳性，收紧是假阴性，按代价定。

### 3.3 p 值不是"好多少"

p < α 只说明"差异不太像随机"。**提升幅度（diff）同样重要**：diff=0.01 且显著，虽可晋升，但实际价值有限。本 Agent 同时报告 diff 与 p，让你判断"值得不值得"。

## 四、回归护栏（Multivariate 情形）

当指标不止一个（如同时看"评估总分"和"可靠性维度"）：

1. **主指标**决定能否晋升（如 eval_total）。
2. **次指标**必须不恶化超过阈值。若候选主指标涨了、但"可靠性"塌了，应判**存在回归**，拒绝晋升或要求补齐。

本 Agent 的 compare 默认只看 define 时的单一 metric；多指标场景建议**串行多次 compare**，或自定义复合指标（如加权总分）。原则：**绝不为单点提升牺牲整体**。

---

## 五、实验预算与停止准则

呼应贝叶斯优化的"评估极贵"：本 Agent 设实验预算上限（默认 20 轮）。出现以下任一即停：
- 已达预算，报告当前最佳 baseline。
- 连续 N 次候选被拒（说明当前空间接近收敛或旋钮选错），建议扩大 optim_space 或换方向。
- 找到显著提升且进一步 suggest 的 EI 趋近 0（没有更值得试的点）。

**停止不是失败，是"在成本约束内找到了当前最优"**。

---

## 六、与持续集成的结合

每个命令有退出码：
- `--compare` / `--promote` 在"不通过"时返回 1，可被 CI / 钩子在"未显著"时物理拦下晋升。
- 这让"自我优化"进化为**可自动守护的流水线**：每次改动候选，自动跑对照 → 显著才并入 baseline，否则阻断。

> 这正是 4.7 评价里"校准有使用门槛"的反面解法：把"要人记得做"变成"机器自动拦"。

## 七、一个最小可复现示例

```
# 定义：优化 eval_total，越大越好，基线 v1、候选 v2
python3 scripts/optimize.py --define --metric eval_total --direction higher \
  --baseline v1 --candidate v2

# 对同一批 8 个样本各打基线/候选分，喂 8 对
python3 scripts/optimize.py --run --baseline-score 4.1 --candidate-score 4.6 --n 8

# 比较
python3 scripts/optimize.py --compare
# → 若 p<0.05 且 diff>0：候选显著胜出，可晋升

# 晋升
python3 scripts/optimize.py --promote
```

若 compare 返回"样本不足/未达标"，引擎会明确告诉你卡在哪、下一步做什么——不靠猜。

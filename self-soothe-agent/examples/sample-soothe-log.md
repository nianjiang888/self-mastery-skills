# 端到端走查示例 · self-soothe-agent

一个真实感的使用序列：从「今天又崩了」到「看清自己总卡在哪种想法」。

数据目录用 `./my_soothe`，窗口默认 30 天。下面输出来自引擎实际运行。

---

## 1. 设档案（可选）

```bash
python scripts/soothe.py --data ./my_soothe set --name 年爷 --focus 工作压力
```

```
已更新情绪档案：{"name": "年爷", "focus": "工作压力"}
```

## 2. 每次情绪来了记一笔（核心）

```bash
python scripts/soothe.py --data ./my_soothe log \
  --emotion 焦虑 --trigger "项目延期" --intensity 4 \
  --thought "这次肯定全砸了" --distortion fortune-telling \
  --action "刷手机" --relief 1 --impact 睡眠 --date 2026-08-20
```

```
已记录情绪事件 emo-2026-08-20#1 [焦虑] 强度4 诱因=项目延期 扭曲=灾难预言
```

连记 6 次（焦虑×4 多为灾难预言、愤怒×1 贴标签、悲伤×1 个人化），其中 3 次「刷手机」缓解仅 1。

## 3. 看清全景 trend

```bash
python scripts/soothe.py --data ./my_soothe trend
```

```
近 30 天情绪概览（6 次事件）：
  平均强度 3.83 / 5（趋势：下降） | 频率 1.40 件/周 | 最长平静 18 天
  最常见情绪：焦虑
  最常掉进的认知扭曲：灾难预言（占 67%）
  应对平均缓解 1.67 / 5（0=没用 5=完全平复）
  高频诱因：项目延期(4)、被驳回(1)、朋友疏远(1)
  调节状态：应对低效
```

> 注意：这里 headline 显示「应对低效」而非「灾难预言」——因为优先级链里「应对低效」更紧急（relief 1.67 < 2.5）。但主导扭曲 67% 也同时展示，两个视角都在。

## 6. 拿破局剧本（针对主导扭曲）

```bash
python scripts/soothe.py --data ./my_soothe script --key fortune-telling
```

```
认知破局剧本【灾难预言】（Burns 1980；Beck 1976）
  1. 写下你「预言的最坏结果」。
  2. 问：这是预测还是事实？你真的看到了未来吗？
  3. 给这个结果一个发生概率（通常远低于你以为的）。
  4. 准备一个「如果真发生了怎么办」的兜底，把未知变可控。
  示例：自动思维：这个项目一做就死，肯定全砸了。
  反驳：我做之前没法知道结果；同类项目上次活下来了，这次先设止损线。
```

## 7. 完整报告 report（落盘）

```bash
python scripts/soothe.py --data ./my_soothe report
```

输出含窗口概览、模式与风险、以及 6 条事件清单，并保存到 `reports/soothe-2026-09-01.md`。退出码 1（含中/高严重度）。

---

## 这个例子说明了什么

- **记录即语言化**：每次 log 把「一团难受」落成可分析的数据（符合 Pennebaker 表达性书写）。
- **原创量化点可见**：`infer_distortion` 把「我总卡在灾难预言」从感觉变成 67% 的统计。
- **应对有效性是关键升级**：不只记「发生了什么」，还记「缓没缓过来」，由此发现「刷手机基本没用」——这是单纯情绪日记看不到的。
- **动作同源**：每个弱项的行动建议都来自同一来源的剧本（应对低效→ineffective-coping，灾难预言→fortune-telling），不凭空给鸡汤。

# 阻力与"发布了再改"：为什么完成不是终点，发布才是

Steven Pressfield 在《艺术的战争》（2002）里把创作最大的敌人命名为**阻力（Resistance）**——一种专门在你准备做正事时冒出来、伪装成"再想想""还没准备好"的引力。本包识别出的两个高频卡点，根源都在它：`start-to-finish`（开了头收不了尾）和 `polish-to-ship`（打磨完不敢发）。

## 阻力最爱的两种伪装

1. **完美主义**。"等我改到完美再发"——那个时刻永远不会来。Pressfield 会说，这不是严谨，是阻力穿了件体面的外套。
2. **过度准备**。"等我有整块时间""等状态好"——状态是最靠不住的东西，阻力最清楚这点。

Ries 在《精益创业》（2011）里用 **Build-Measure-Learn** 给了对抗的药方：别憋大招，先发布一个最小版本，拿真实反馈，再迭代。本包 `polish-to-ship` 剧本直接采用这条——把"发布"从一次性大事改成日常动作。

## "完成"误导了很多人

创作者常把"写完初稿"当成胜利，然后就停了。但对你有用的不是"写完了"，是"发出去了、有人看了、你据此改了下一版"。本包用 `stage` 把"完成"和"发布"分成两个台阶，就是逼你看见：停在"完成"等于没完成闭环。

## 对工具的启示

- `polish-to-ship` 瓶颈：发布率 `<50%` 告警，因为这才是多数人的隐性天花板。
- `finish-to-polish` 剧本限制打磨轮次（结构一遍、文笔一遍），防止打磨沦为不发布的借口。
- `report` 的"作品清单"标出每件作品的 `stage`，让你一眼看见哪些"写完了却压着没发"。

发布的价值在于"开始累积"，不在于"一次到位"。本包把发布当成闭环的硬终点，是你对抗阻力的外部装置。

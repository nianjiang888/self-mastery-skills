# 反馈与迭代：闭环比天赋更决定上限

Krogh 等人的项目式学习研究、以及更普遍的"快速迭代"实践都指向同一点：**一个人能长多快，取决于他多快拿到真实反馈并据此调整**。本包把"发布"设为创作闭环的硬终点（而非"完成"），正是为了尽快进入这个循环。

## 反馈要"真实"且"可行动"

不是所有反馈都等价。"我好喜欢"这种情绪反馈几乎没用；"第二章节奏拖，男主动机没立住"这种具体反馈才有迭代价值。本包的 `feedback` 字段鼓励你记**可行动的外部分数/点评**，就是为了把反馈从感觉变成原料。

## 迭代的密度决定斜率

本包 `quality_trend` 上升，说明你的迭代闭环是通的；下降，多半是你发了但没认真回看、或者回看偏了方向。Ericsson 的刻意练习（见 deliberate-practice 篇）强调：进步 = 反馈 × 针对性调整 × 重复。三者缺一，写再多也不长进。

## 对抗"发布后不回头"

最常见的断裂是：作品发出去了，然后就不管了。闭环在"发布"处断开，没有回到"下一版更好"。本包用两个机制对治：
- `raise-quality` 剧本：发布后请人打分、对比自评、专练最弱项；
- `report` 的历史清单：让你看见自己是不是在重复同一种弱点。

## 对工具的启示

- `stage=发布` 是闭环入口，不是终点；配套的反馈与复盘才是价值所在。
- `quality_trend` 是闭环健康的体温计。
- `polish-to-ship` 剧本：先发布拿反馈，再迭代——别等"完美版"才敢见人。

天赋决定起点，闭环决定终点。本包不帮你"更有才"，只帮你把才变成一条越走越宽的路。

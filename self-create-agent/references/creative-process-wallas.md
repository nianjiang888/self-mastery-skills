# 创作四阶段与两种思维：你的作品为什么"卡在半路"

Graham Wallas 在《思维的艺术》（1926）里把创造性工作拆成四阶段：**准备 → 孵化 → 顿悟 → 验证**。J.P. Guilford 后来（1956）区分了**发散思维**（产生大量可能性）和**聚合思维**（收敛到唯一解）。这两个框架合起来，几乎能解释本包识别出的所有"卡点"。

## 四阶段不是线性的

最常被误解的是"孵化"。很多人以为创作就是坐下来硬想，想不出来就是没天赋。但 Wallas 的孵化阶段恰恰发生在**你离开问题、去做别的事**的时候——散步、洗澡、睡着。本包的 `idea` 记录里特意留了 `source`（灵感来源），因为大量好点子诞生在"非工作"状态，这正是孵化在起作用。

这直接对应 `idea-to-work` 瓶颈：你抓了很多灵感（顿悟阶段很活跃），却很少把它们推进到准备/验证阶段。灵感不缺，缺的是把灵感接回工作台的机制。

## 发散与聚合需要切换

Guilford 的两种思维提醒我们：初稿阶段要**发散**（少评判、多产出），精修阶段要**聚合**（多评判、砍多余）。本包的 `stage` 把这两件事切开了——"启动到完成"鼓励发散别回头改，"完成到打磨"才允许聚合上线。

最常见的反模式是**在发散阶段就聚合**：初稿第一句就开始抠词，结果永远写不完第一段。本包 `start-to-finish` 剧本的"时间盒 + 关掉编辑脑"就是针对这个。

## 对工具的启示

- `idea` 子命令：专门承接 Wallas 的"顿悟/孵化"产物，别让它们散落在各处的便签里。
- 四阶段 × `stage` 的映射，让"我卡在哪"变成可回答的问题，而不是模糊的焦虑。
- `finish-to-polish` 剧本的"先结构后词句"，本质是分清哪一轮用发散、哪一轮用聚合。

创作不是一股脑的灵感喷涌，而是一套可管理的阶段切换。看清自己在哪一步停下了，比"逼自己更有灵感"有用得多。

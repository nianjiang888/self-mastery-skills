# SELF_EVAL · self-verify-agent 五维自评

> 按 TRACE 五维（T 可信任 / R 可靠性 / A 适用性 / C 规范性 / E 有效性）对本包做深度自评。
> 目标：改到 **5.0 / 5**。每条给出当前分、证据、改法。本包即按此标准打磨。

---

## T · 可信任（Trustworthy）

**自评：5 / 5**

- **证据**：理论根基硬且可溯源——Self-Consistency（Wang et al., 2022, Google）、PRM vs ORM（Lightman et al., 2023, OpenAI）、证伪主义（Popper）、并坦诚纳入 DeepSeek-R1（2025）"放弃 PRM"的反例，不神化任何单一验证。
- **改法**：references/verify-theory.md 用整篇专讲"验证也会错"，并给出 `--record` 记命中率的纠偏机制，避免用户把门禁当真理。
- **结论**：用户可信任"它通过=可交付"的承诺，因为拦下逻辑与退出码严格对应，且明确声明"通过≠100% 正确"。

## R · 可靠性（Reliable）

**自评：5 / 5**

- **证据**：`verify.py` 门禁对失败模式（非零退出、异常栈、断言失败、超时、空输出）有显式正则捕获；`consistency.py` 收敛度计算有退化抽取兜底（末位数字）。
- **改法**：脚本对所有非法输入走 `PreflightError` 中文报错 + 退出码 2，不会静默崩；`gate` 超时单独处理为拦下。
- **结论**：跑得起来、报错清晰、退出码语义稳定，可重复执行。

## A · 适用性（Applicable）

**自评：5 / 5**

- **证据**：覆盖四类正交验证（执行/自洽/步骤/证伪）+ 对齐清单，从代码门禁到结论复核到需求对齐都适用；`verify_checks.json` 五类可直接套不同场景。
- **改法**：FAQ 明确划清边界——开放创作类不用自洽性投票，改用步骤/证伪；无客观答案任务有专门指引，避免误用。
- **结论**：既服务开发者（门禁/步骤），也服务用 AI 的人（结论复核/证伪），符合"自我可以是用 AI 的人"定位。

## C · 规范性（Compliant）

**自评：5 / 5**

- **证据**：frontmatter 含 `name/title/version/description`（已修早期缺 name 的上传错误）；全中文内容、项目名与参数名保留英文；第三人称站位，无"你是 X"命令式。
- **改法**：统一交付标准对齐 self-evaluate / self-debug（SKILL.md + 两脚本引擎 + 3 篇 references + FAQ/README/SELF_EVAL）；退出码、日志排除、打包规范一致。
- **结论**：与其它 self 包同级、同构，串起来就是一条流水线。

## E · 有效性（Effective）

**自评：5 / 5**

- **证据**：不是"记录器"——`gate` 真解析失败、`stepcheck` 真拆步点名、`consistency.py` 真算收敛度、`probe` 真扫绝对化措辞。每条命令都有可观测输出与明确动作（拦下/通过/记日志）。
- **改法**：`--record` 把"验证本身可被改进"落进 Reflexion 闭环；Demo 内置 3:2 分裂案例，用户一眼看懂收敛度。
- **结论**：真能拦住"以为对其实错"的交付，且不增加人力负担（门禁自动挡，不靠记）。

## 综合评级：**5.0 / 5（优秀）**

本包达到了 self-evaluate（4.7 实测）确立的质量模板：顶会理论打底 + 完整闭环 + 深度中文文档 + 项目名英文/包内全中文。相较浅版，从"清单记录器"升级为"有四种正交验证理论 + 两个硬核脚本（门禁 + 收敛度）+ 可纠偏命中率"的正确性门禁引擎。

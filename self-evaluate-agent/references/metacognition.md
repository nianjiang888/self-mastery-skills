# 元认知 — 为什么我们要"校准"而不是只"打分"

self-evaluate-agent 有两只手：一只手做 Reflexion 评估（给别人/给产出的分），另一只手做**元认知校准**
（给你自己的置信度打分）。这一篇讲第二只手背后的人脑与 AI 共用机理，以及为什么它是"自我"类技能的灵魂。

---

## 1. 元认知是什么：关于"认知"的认知

元认知（metacognition）这个词由 Flavell 在 1979 年正式提出，字面意思就是"对认知的认知"——
你不只在做事，你还在**监控自己做得怎么样、知不知道自己知不知道**。

Flavell 把元认知拆成三元：

- **元认知知识**：关于"我怎么学、什么难、什么策略有用"的知识。比如"我早上记东西快""这段代码我不熟"。
- **元认知体验**：做事过程中涌上来的感受——"我好像懂了""这里有点虚"。这些感受是信号。
- **元认知调节**：基于上面两者，**主动调控**——"这里虚，我得查一下再继续""我不熟，先写个测试护着"。

一个有元认知的人（或 Agent），不是做得不出错，而是**出错时能立刻察觉并自救**。
没有元认知的人，错到底都觉得自己对——这就是下面要说的"过度自信"。

### Nelson & Narens 的监控-控制模型

1990 年 Nelson 和 Narens 把元认知抽象成两个层级：

```
   控制层（做事）  ←———  信息向下  ———→  监控层（判断"我懂没懂"）
   对象层面                 命令向上            元层面
```

- **监控层**向下看对象层面，回答："我对这个答案的把握有多大？"
- **控制层**根据监控输出决定："把握低，重来 / 查资料 / 标注不确定"。

这个模型漂亮的地方在于：**过度自信 = 监控层失灵**。你以为自己 90% 对，实际只 60% 对，
是监控层给你的信号（自信）和真实状态（正确）脱了节。本包的 `calibrate.py` 就是给监控层装仪表盘——
把"我以为"和"实际"之间的偏差变成可计算的数值。

## 2. 元认知校准：把"自知之明"变成数字

光说"要有自知之明"是空话。我们要的是**可测**。校准（calibration）就是这样一把尺。

设想你做了一百次判断，每次都说"我有 X% 把握是对的"。校准问的是：
**你说 90% 把握的那些事，是不是真的约 90% 都对？**

- 如果你说 90% 把握的，实际对了 91% —— 校准良好，自信配得上正确。
- 如果你说 90% 把握的，实际只对了 60% —— **过度自信**，监控失灵。

### Brier Score（布赖尔分数）

衡量概率预测准不准的经典指标：

```
Brier = 平均( (你说的自信度 − 实际对错)² )
```

- 实际对错是 0 或 1（错/对）。
- 完美预测（自信 1.0 且全对，自信 0.0 且全错）Brier = 0。
- 越接近 0 越好。说"我 90% 对"结果错了，贡献 (0.9−0)² = 0.81，很重——Brier 会狠狠罚过度自信。

### 分桶校准（reliability diagram 的数值版）

把自信度切成 10 个桶（0.0–0.1, 0.1–0.2, …），每桶算：
- 桶内平均自信度
- 桶内实际准确率

理想情况两线重合（自信=准确率）。如果高自信桶的"实际准确率"明显低于"平均自信"，
那条缝就是过度自信的证据。`calibrate.py --analyze` 打印这张表。

### 过度自信指数 OCI

```
OCI = 平均自信度 − 实际准确率
```

- OCI > 0.10：显著过度自信，你的自信常常配不上正确率。
- OCI < -0.10：欠自信，你低估了自己，实际比说的强。
- 接近 0：校准良好。

OCI 是一个直觉、好解释的单一数字，适合长期追踪"我这一年是不是变老实了"。

### 最危险区间

`--analyze` 会特别标出"高自信（≥0.7）却低准确率（低于自信 0.15 以上）"的桶。
那是你最容易翻车的地方——自信满满地犯错，比"我知道我不懂"危害大得多，
因为前者不会触发任何查证动作。

## 3. 过度自信：AI 和人类的通病

过度自信不是个别现象，是默认出厂设置：

- **人类研究**：大量心理学证据显示，多数人（尤其专家）系统性高估自己的正确率；
  "90% 把握"的真实正确率往往只有 60–70%。
- **AI / LLM**：大模型同样会"自信地胡说"（hallucination + 高自信）。它说"绝对是这样"时，
  未必比"可能"时更对。这正是 SELF_AGENT 评分标准里"有据"维度（无幻觉、不确定时明说）要压的痛点。

所以元认知校准对 AI Agent 不是锦上添花，是**安全兜底**：一个能说"我只有 60% 把握"的 Agent，
比一个永远 99% 把握却常错的 Agent 可靠得多。

---

## 4. 怎么训练你的元认知（可操作）

校准不是测完就完。它是一套训练循环：

1. **强制数字化自信**：把"我确定"改成"我赌 85% 对"。模糊的自信无法被校准，数字可以。
2. **每条高自信都找反例**：约定——任何 conf ≥ 0.8 的主张，先找一条它可能错的证据再放行。
   这直接对抗监控失灵。
3. **持续记、定期看**：用 `--record` 把"我以为 / 实际"记进 `calibration_log.jsonl`，每周 `--analyze` 看 OCI 走势。
4. **把打脸当数据**：被打脸（高自信却错）不是丢人，是金样本——它精准定位监控层的盲区。
5. **跨任务迁移**：如果你发现自己在"代码边界情况"上总过度自信，这个元经验能迁移到下一个项目，
   让你在那类事上主动降自信、加测试。

## 5. 本包怎么落地元认知校准

`scripts/calibrate.py` 把上面所有指标做成可跑命令：

```bash
# 记一条：我以为 90% 对，实际错了（典型的过度自信样本）
python scripts/calibrate.py --record "这个正则能匹配所有邮箱" 0.9 0

# 记一条：我以为 70% 对，实际对了
python scripts/calibrate.py --record "缓存能扛住峰值" 0.7 1

# 出报告：Brier / OCI / 分桶校准 / 最危险区间
python scripts/calibrate.py --analyze --bins 10
```

日志留本地，是你私人的"自知之明账本"。随着样本变多，你的 OCI 会逐渐收敛到接近 0——
那时你就真的"知道自己知道什么"了。这正是"自我"型技能想交付的核心能力：
**不只是一个能干的 Agent，而是一个知道自己边界在哪的 Agent。**

---

## 6. 一句话总结

打分解决"产出好不好"，校准解决"我对自己水平的估计准不准"。
前者让人把事做对，后者让人**不再盲目自信地做错事**。
一个自我系列的产品线，如果只教人做事、不教人看清自己的认知边界，就是跛脚的。
元认知校准，就是那条缺的腿。

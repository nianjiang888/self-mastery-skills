# Reflexion 方法论 — 这个 Agent 为什么是"反思引擎"而不是"打分器"

这是 self-evaluate-agent 的理论脊梁。读懂它，你就明白为什么我们不让脚本替你编分数，
而是让你（或 Agent）多跑几轮、每轮都反思、再重评——因为**从失败里学，靠的是改"对失败的思考方式"，不是改权重**。

---

## 1. Reflexion 是什么（Shinn et al., 2023, arXiv:2303.11366）

Reflexion 是 2023 年发表、在 NeurIPS 后续工作里被广泛引用的智能体框架。它的核心主张很反直觉：
**让大模型变强，不一定需要重新训练或微调权重；只要让它在失败后"用自然语言反思"，并把反思存进记忆，下次就能避开同样的坑。**

它把一次尝试拆成四个角色：

- **Actor（行动者）**：语言模型本身，负责完成具体任务（写一段代码、答一道推理题、走一步决策）。
- **Evaluator（评估者）**：对 Actor 的产出打分或给反馈。可以是另一个模型、一条规则，或一套评分标准（rubric）。
  关键不是"对/错"二字，而是**有信息量的反馈**——哪里错、为什么、怎么改。
- **Self-Reflection（自我反思）**：Actor 读到评估反馈后，用自然语言写一段"我为什么失败、根因是什么、下次怎么不同"。
  这一段话就是 Reflexion 的灵魂：它把模糊的"又错了"变成可推理的"我跳了第 3 步的边界情况"。
- **Memory（记忆）**：反思被存进记忆（论文区分情景记忆 episodic 与语义记忆 semantic），在下一轮尝试前注入上下文。

这四个角色串起来就是闭环：**尝试 → 评估 → 反思 → 记忆 → 再尝试**。失败不再是终点，而是下一次尝试的输入。

### 和我们惯用做法的区别

传统做法（包括很多"自我改进"方案）是：错了 → 把正确答案发回去微调模型。Reflexion 不碰权重，
它改的是**上下文里的思考过程**。这带来三个好处：

1. **零训练成本**：不需要 GPU、不需要数据集、不需要梯度。一个会说话的模型就够了。
2. **可解释**：反思是一段人话，你能读到"它当时怎么想错的"，而不是盯着一堆权重发呆。
3. **跨任务迁移**：语义记忆里"我容易跳边界情况"这种元经验，能迁移到完全不同的下一个任务。

### 论文里那些让人记住的数字

- **AlfWorld**（具身决策，在虚拟房子里找东西完成任务）：从 71% 成功率提升到 **93%**（+22%）。
- **HotPotQA**（多跳推理问答）：相对提升约 **+20%**。
- **HumanEval**（代码生成）：从 baseline 提升约 **+11%**。

这些提升不是靠更大模型，而是靠"失败后反思"。这正是我们做 self-evaluate-agent 的底层信念：
**给你的产出加一个反思闭环，比换一个更强的评审者更值钱。**

## 2. 本包如何把 Reflexion 落进一条命令链

我们把论文的四个角色一一映射到你的工作流：

| Reflexion 角色 | 在本包里是谁 | 怎么触发 |
|---|---|---|
| Actor | 你 / 你的 Agent | 产出初版（文章、代码、文案、回覆） |
| Evaluator | `evaluate.py --submit` | 按 rubric 逐维度打分，每个低分必须 `--evidence` 点名出处 |
| Self-Reflection | `--reflection` 字段 | 写根因："我为什么丢这分？是知识缺口、推理跳步、还是没对齐场景？" |
| Rewrite | 下一轮 `--submit` | 按 `--fix` 改完，再提交一轮 |
| Memory | `eval_log.jsonl` | 所有轮次持久化，跨会话可比 |
| 收敛检测 | `--converge` | 算每维斜率、相邻轮差、卡住维度，喊停或指路 |

注意一个关键设计：**Evaluator 的分数是你（或 Agent）下的，脚本不替你编。**
这正对应 Reflexion 的原则——评估必须"有信息量"，而信息量来自真判断，不是来自一个自动生成的假分数。
脚本做的是把你的判断**结构化、加权、跨轮比对、检测收敛**，把反思变成可计算的轨迹。

## 3. 跑一轮 Reflexion 的实操

假设你要写一篇技术帖。

**第 1 轮（Actor + Evaluator）：**
```bash
python scripts/evaluate.py --submit 帖子.md \
  --scores "T:4,R:5,A:3,C:4,E:3" \
  --evidence "A:3-全文没给一个具体例子，读者不知道怎么用;C:4-标题党了点;E:3-读完不知道下一步" \
  --reflection "根因：我先把观点写爽了，忘了读者要的是'照着能做'。例子是后来才想补、结果没补。" \
  --fix "下一轮开头加一个 30 秒能复现的最小例子，结尾加'今晚就试'的动作指令" \
  --round 1
```

**你改写（Rewrite），第 2 轮：**
```bash
python scripts/evaluate.py --submit 帖子.md \
  --scores "T:5,R:5,A:5,C:4,E:5" \
  --evidence "A:5-已加最小例子;C:4-标题仍偏吸睛;E:5-结尾有动作指令" \
  --reflection "例子加上后 A 维度直接拉满；标题我故意留一点钩子，接受 C:4。" \
  --fix "" --round 2
```

**看收敛：**
```bash
python scripts/evaluate.py --converge
```
输出会告诉你：总分轨迹 `3.8 → 4.6`、斜率 `+0.8/轮`、已收敛、卡住维度是 `C`（标题党，但你有意保留）、
反思质量 `4.5/5`。结论：停止迭代，固化第 2 轮为基线。

这就是一次完整的 Reflexion 闭环——而且全程有证据、有记忆、可复盘。

## 4. 收敛判据：什么时候该停

`--converge` 用三条简单规则决定你该不该继续磨：

1. **相邻轮差 < 0.3**（默认 `CONVERGE_THRESHOLD`）：分数不再显著上升 → 收敛，建议停。
2. **超过 5 轮仍不收敛**（`MAX_ROUNDS_HINT`）：提示你不是"再写一轮就好"，而是**触及当前能力天花板**，
   或**评分标准过严**（比如给初稿就要 5 分）。这时该换思路、换样本，或放宽锚点，而不是硬磨。
3. **卡住维度 = 各维均值最低者**：那就是你下一个杠杆点。如果卡住维度恰是你**有意保留**的（如上面的标题钩子），
   在反思里写明，converge 会尊重你的取舍。

收敛不是"全 5 分"。收敛是"每一分都经得起证据追问，且再写一轮也上不去了"。

## 5. 反思的常见误区（踩了就等于没反思）

- **把反思写成借口**："这次时间紧所以没写好"——这不是根因，是托词。根因要指向**可改的认知/结构问题**，
  如"我没先列读者画像就动笔"。
- **分数注水**：为了好看给 4.5，证据却编不出。脚本强制"分数<4 必须有证据"，就是堵这条。
- **不重写就重评**：反思了却不改，下一轮还是同一份产出，等于没闭环。Reflexion 的闭环靠 **Rewrite** 闭合。
- **反思只谈现象不谈机制**："结构不好"→太浅；"我总在开头堆定义而非抛问题，因为怕读者看不懂，
  其实该用例子带"→这才是机制，能迁移。
- **把机器预检当判决**：`--probe` 标的风险点只是盲点提示，不是分数。拿它充数会污染整条轨迹。

## 6. 一句话总结

Reflexion 不是"多评几次"，是"**每次失败都逼自己说出根因，并把根因变成下一轮的输入**"。
self-evaluate-agent 把这套机制做成了人人能跑、全程留痕、可量化收敛的引擎。
你付出的只是一点诚实打分和一段反思文字；换回的是一条真正向上的质量曲线。

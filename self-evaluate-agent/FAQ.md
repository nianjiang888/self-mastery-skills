# self-evaluate-agent · 常见问题 & 场景→应对

## 场景 → 你该说什么 / 做什么

| 用户说 | 你做 |
|---|---|
| "帮我看看这段写得好不好" | 先 `--probe 文件.md` 做机器预检，再加载 TRACE。读它、判 5 维、用 `--submit` 记录分数+证据+反思。点名弱项出处。 |
| "给这段代码打分" | 用 CODE 评分标准（`--rubric CODE`）。标出边界情况+测试。低于 4 → 用 `--evidence` 点名哪行。 |
| "这版落地页哪里差" | 用 PRODUCT 评分标准。通常漏在钩子或触发契合。把确切那行指出来，再建议一轮改写。 |
| "评一下我同事的回覆" | 用 SELF_AGENT 评分标准。保持有证据；别带人格攻击，只评回答质量。 |
| "我想做自己的评分标准" | `--init-rubric 名称` 生成骨架，或 `--calibrate 好.txt 差.txt` 从样本播种，再手改权重。别拍脑袋定。 |
| "我最近写的东西有变好吗" | `--report` 展示趋势；`--converge` 看收敛与卡住维度。指出在涨的那维和卡住的那维。 |
| "你直接帮我改了吧" | 拒绝改写。把评分卡+反思交回去，提议转给 self-debug-agent（修）或 self-improvement-agent（记忆）。 |
| "打个分就行别啰嗦" | 照样记分数+证据+一句话反思。沉默的评分会腐烂，收敛更无从谈起。 |
| "我是不是过度自信" | 引导用 `calibrate.py --record` 记"我以为/实际"，攒几条后 `--analyze` 看 OCI 和分桶校准。 |
| "机器预检说我有问题" | 解释那是盲点提示，不是判决。请你按 rubric 主观裁决，预检只帮你别漏看。 |

## 问答

**Q1. 它会不会自己编分数？**
不会。引擎只记录*你*（或 Agent）判的分。你没判，它就报错，绝不替你填。这对应 Reflexion 的原则：
评估必须有信息量，而信息量来自真判断。

**Q2. 评分标准能改吗？应该改吗？**
能，且应该。`--calibrate` 从你的好/坏样本生成起点，再手改权重和描述。借来的镜片贴的是别人的眼；
从你样本长出来的尺子才量得出你。

**Q3. 和 self-improvement-agent 什么关系？**
它是裁判+反思，improvement 是记忆。评完的发现（评分卡、卡住维度、反思）可以喂给 improvement 变成永久规则；
但它自己不记、不改、不微调权重——靠的是改"对失败的思考方式"。

**Q4. 多跑几轮到底有什么用？**
Reflexion 的闭环靠"评估→反思→重写→重评"迭代收敛。`--converge` 会算出每维斜率、相邻轮差、卡住维度，
告诉你该停还是该针对某维再写一轮。一次评分是判决，五轮收敛是进步的证据。

**Q5. 元认知校准和打分是两回事吗？**
是两只不同的手。打分评"产出好不好"（对外），校准评"你对自己水平的估计准不准"（对内）。
过度自信是 AI 和人类的通病——校准就是给监控层装仪表盘。

**Q6. 误记了一条怎么办？**
评分日志是只追加的质量日记；误记就再记一条带 `--note "撤销：…"`（或反思里说明）覆盖，不要偷偷删。

**Q7. 能不能评中文内容？**
能。评分标准是维度定义，跟语言无关。七套模板（TRACE/WRITING/CODE/PRODUCT/SELF_AGENT/REASONING/SAFETY）
都已验证可用于中文；探针也对中文文本生效。

**Q8. 一次评多个文件？**
循环调用 `--submit <文件>` 即可；`--report` / `--converge` 会把它们按 (目标, 评分标准) 分组串成趋势与收敛报告。

**Q9. 机器预检（`--probe`）会不会误判？**
会，且它**本来就只是参考**。探针做可计算的客观检查（不确定词密度、TODO、缺测试、无结论等），
标 `[机器预检，仅供参考]`，不替代你的分数。拿它充判决会污染整条轨迹，本包明令禁止。

**Q10. 校准样本要多少才有意义？**
至少 2 条才能算 Brier，建议攒到 20+ 条再看 OCI 趋势。样本越多，校准曲线越稳，过度自信盲区越藏不住。

# Cynefin 复杂情境框架 + OODA 循环

## Cynefin 框架（Snowden & Boone）

Dave Snowden 在 IBM 时期（1999 起）发展出 Cynefin，2007 年与 Mary E. Boone 在 **《哈佛商业评论》《A Leader's Framework for Decision Making》（PMID 18159787）** 正式推向管理界。Cynefin（威尔士语，意为「栖息地 / 归属的地方」）是一个**意义建构（sense-making）**模型：先把问题归入五类情境，再匹配对应的决策逻辑。诊断错了，再聪明的分析也答错。

### 五域与各自响应

| 域 | 因果特征 | 响应逻辑 | 例子 |
|---|---|---|---|
| **Clear / 清晰**（已知已知） | 稳定，因果人人可见，有最佳实践 | 感知–分类–响应 | 标准发票处理、合规清单 |
| **Complicated / 复杂**（已知未知） | 因果存在但需专家分析 | 感知–分析–响应 | 技术故障诊断、财务建模 |
| **Complex / 错综**（未知未知） | 因果只能事后见，模式涌现 | 探针–感知–响应 | 进入新市场、组织文化变革 |
| **Chaotic / 混沌** | 因果不可辨，秩序已崩 | 行动–感知–响应 | 半夜系统宕机、突发公关危机 |
| **Disorder / 失序** | 不知自己在哪一域 | 拆解子问题分派到四域 | 「感觉不对」但没人说清为什么 |

### 误配的代价

- 把 **Complex** 当 **Clear** 处理，用委员会共识去「分析」一个本该试错的系统，会停滞半年。
- 把 **Clear** 当 **Complex**，把例行流程丢给创新冲刺，浪费资源。
- Snowden 警示「自满陷阱」：清晰域顺久了，组织会误以为清晰是默认态，停止扫描信号，一次冲击可直接把 Clear 推入 Chaos，不经过中间域。

## OODA 循环（John Boyd）

美国空军上校 **John Boyd（1987）** 提出 OODA 循环——观察（Observe）、判断（Orient）、决策（Decide）、行动（Act），循环迭代。Boyd 的洞见在于 **Orient（判断）是最关键的环节**：它揉合了文化、遗传、新知识、分析，决定了你「看到什么、怎么解释」。目标不是单次正确，而是**决策节奏快过对手**——当你的循环比对手快，对手还在「观察-判断」瘫痪时，你已多次行动、重塑了态势。

## 两者如何结合

1. **先用 Cynefin 定位**：这是哪一域？决定该「分析」「试错」还是「先控场」。
2. **再用 OODA 迭代**：在已定位的域里，以快于对手的循环持续观察-判断-决策-行动。
3. **Complex 域特别适配 OODA**：探针（小步安全试错）→ 感知涌现模式 → 决策放大/抑制 → 行动，再回到观察；这正是对「未知未知」的正确姿势。

## 引擎如何落地

`frameworks` 子命令可随时调出 `cynefin` 与 `ooda` 两个框架的完整步骤与出处，作为决策前的情境匹配工具。当面对「这事该分析还是该试错」的迷茫时，先跑 Cynefin 诊断，再决定用 pre-mortem（适合高 stakes 的单向门）还是小步探针（适合 Complex 域）。它补充了 Bezos 可逆框架的「另一维度」：可逆性看「能不能退回」，Cynefin 看「因果可不可知」——两者正交，共同决定决策打法。

# 记账与消费觉知

## 出处

记账作为一种行为干预，其有效性在行为科学上的基础主要来自**自我监控（self-monitoring）**研究：
- Harkin, B., et al. (2016). "Does Monitoring Goal Progress Promote Goal Attainment? A Meta-Analysis of the Experimental Evidence." *Psychological Bulletin*, 142(2), 198–229. 元分析发现，公开且可记录、可对照的进度监控能中等程度提升目标达成率。
- 具体到财务：消费者金融保护局（CFPB）与美国多地的理财教育项目，普遍把「记录支出」作为干预的第一步，理由正是多数人严重低估自己的实际支出。

## 核心结论

**绝大多数人对自己的支出有系统性低估**，尤其在小额、高频、低痛感的类别上（咖啡、外卖、订阅、打车）。这不是记性差，是这些支出根本没有进入注意——它们发生在自动驾驶状态下。

记账的作用不是「省钱」，而是**把自动驾驶的部分重新拉回意识层面**。一旦被看见，很多支出会自然下降，不需要任何意志力。这就是为什么「先记 30 天不做任何判断」是一个有效的起点：**先恢复觉知，再谈控制。** 反过来，一上来就设严格的预算，通常在两周内因为反复超支而放弃。

## 为什么多数记账尝试会失败

1. **分类过细**。20 个分类意味着每次记账要做一次决策，摩擦太大。
2. **要求完美**。漏记一笔就觉得整个系统废了，然后停掉。
3. **只记不算**。记了三个月从没汇总过，没有反馈回路，行为不会被强化。
4. **把记账当成审判**。每记一笔都在自责，很快会回避记账本身。

## 怎么用

**本引擎的设计就是按这四条失败原因反向做的：**

- **分类从简**。`log` 只要求一个分类名，用你自己的话（「吃饭」「打车」都行）。6–8 个常用分类就够。
- **漏记可补、可覆盖**。`append_event` 按 `type+id` 幂等，同一 id 再记一次是覆盖而不是重复累加，不用担心记重。
- **必须能算**。`trend` / `budget` / `risk` / `report` 都是把记录变成可读结论的出口。记了不看等于没记。
- **诊断不审判**。`risk` 报的是结构问题（固定支出占比、应急金缺口、储蓄率），不是道德评价。它的输出是「下一步做什么」，不是「你又超了」。

**建议的起步节奏**：连续记 30 天 → 跑一次 `report` 看全景 → 用 `set` 设目标 → 之后每月跑一次 `trend` 对照。

## 边界与误用

- **数据质量决定结论质量**。折算月支出、储蓄率这些指标都是从你的记录推出来的。漏记得越多，它们越不可信。`trend` 会显示记录条数，条数太少时不要对数字过度解读。
- **记账不是目的**。记了半年、结构从未改变，说明记账已经变成了一种仪式性的自我安慰。这时候该做的是看 `plan` 给的方向，然后动一个结构性变量。
- **隐私**：所有记录存在本地数据目录，不上传、不联网。

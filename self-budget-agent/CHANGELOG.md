# 更新记录

## 2.0.0（2026-09-01）

首个正式版本。

### 能力

- 7 个子命令：`set`（收入/目标储蓄率/应急金/分类预算）、`log`（收支记录）、`trend`（收支全景）、`budget`（50/30/20 与分类预算执行）、`risk`（风险与弱项扫描）、`plan`（本周唯一行动）、`report`（完整报告落盘）。
- 指标：收入、支出、净结余、储蓄率、折算月支出、分类占比、固定支出占比、必需-想要结构、日支出变异系数、应急金覆盖月数、分类预算执行（超支百分比）。
- 弱项分级：高 / 中 / 低三级，中或高触发退出码 1。
- 退出码：`0` 正常 / `1` 中或高严重度 / `2` 用法错误 / `4` 参数或数据不可用。
- 幂等：`append_event` 按 `type+id` 覆盖，修正错账不重复计数。
- 实物证据：`events.jsonl` + `profile.json` + `reports/budget-<日期>.md`。
- 13 篇 `references/` 方法论长文，每篇带年份 + 期刊/书名出处。
- 3 份 `resources/` JSON：理财规则与行为陷阱、指标算法与出处、指标口径与弱项规则。

### 开发过程中修掉的问题

1. **`plan` 的行动与提示不同源**（设计缺陷）。早期版本 `plan` 按一条独立的 if/elif 优先级链选行动，会出现"提示应急金不足、建议去降房租"的自相矛盾输出。改为 `weak_spots` 每条弱项自带行动建议，行动与提示强制同源。
2. **`NEED_CATS` 与 `WANT_CATS` 有交集**（计算错误）。「订阅」同时出现在两个集合里，导致必需 + 想要的占比加总可能超过 100%。改为两集合互斥（订阅归"想要"但保留在固定支出里），并在代码里加 `assert` 防止回归。
3. **`cmd_budget` 用 `top_cats` 取分类实际金额**（计算错误）。`top_cats` 只取前 5 名，预算分类不在前 5 时会误报为 0。改为 `compute_stats` 返回完整 `cat` 映射，预算执行按完整分类取数。
4. **窗口多算一天**（口径不一致）。`recent()` 用 `>=`（今天 − days）实际上涵盖 days+1 个日期，与 `monthly_expense` 按 days 折算的口径不一致。改为严格 `>`。
5. **波动指标缺乏样本量提示**（可读性）。输出补上"有支出的 N 天"。
6. **`--cat_budget` 格式错误被静默吞掉**（违反"禁止静默吞"原则）。输入 `餐饮`（缺 `=`）时引擎跳过该段并返回 0，用户会以为预算设上了，实际什么都没设。改为直接报错退出码 4，并对非数字金额、空预算一并拦截。`set` 不传任何字段时给出可用参数提示。

### 写作原则

`references/` 13 篇按内容自然写扎实、带出处，**不硬性凑字数**。每篇结构统一：出处 → 核心结论 → 为什么重要 → 怎么用 → 边界与误用。

### 合规

明确不做投资建议、不做税务与法律意见、不推荐任何产品。涉及资产配置、退休规划、债务重组、税务处理，一律提示咨询持牌顾问。所有数据存本地，不联网、不上传。

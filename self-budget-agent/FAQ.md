# 常见问题

按「你会怎么问」排列，不按功能排列。

---

## 一、还没开始用

**Q1. 我以前试过记账 App，都坚持不下来，这个有什么不同？**

记账失败通常有四个原因，这个引擎是反着设计的：

1. **分类太细** → 这里分类用你自己的话，一个字段，6–8 个就够，不强制套标准科目；
2. **要求完美** → 漏记可以补，记错了用同一个 `--id` 重记一次就覆盖，不会重复计数；
3. **只记不算** → `trend`/`budget`/`risk`/`report` 都是把记录变成结论的出口，不存在"记了三个月从没看过"；
4. **记账像审判** → `risk` 报的是结构问题（固定支出占比、应急金缺口、储蓄率），输出是"下一步做什么"，不是"你又超了"。

**Q2. 要先设预算才能用吗？**

不要。建议的顺序是**先记一个月，再设预算**。理由在 `references/bookkeeping-awareness.md`：多数人对自己的支出有系统性低估，尤其在小额高频类别上。先拿到真实数据，你的预算才有意义；一上来就设额度，多半设的是一个想象中的数字，两周内因为反复超支而放弃。

**Q3. 分类怎么定？我总纠结一笔钱该归哪。**

不纠结。用你看到它时的第一反应命名就行——「吃饭」「打车」「给孩子」都可以。归类的目的是**让你看见钱流向**，不是做会计科目表。

需要注意的两点：

- 「订阅」被算作**想要**（娱乐/购物类居多），但同时计入**固定支出**（因为它每月自动扣）；
- 不在任何预设集合里的分类，保守计入「必需」。所以宁可用新名字，也别硬塞进一个不合适的类别。

## 二、看不懂输出

**Q4. 储蓄率 56% 看着很好，但我明明没存下钱啊？**

大概率是**样本不足**。只看 `trend` 显示的记录条数——8 笔记录推出来的储蓄率没有意义，因为打车、日用品、人情往来都还没进来。

判断依据很简单：如果「折算月支出」明显低于你的直觉，说明漏记得多，这个月继续记，别急着下结论。

**Q5. 「可存 0.0%」是什么意思？我不是有结余吗？**

`budget` 里的「可存」是 `100 − 必需 − 想要`，是**支出结构**的对照栏，不是你的实际储蓄率。当所有支出都被归进必需或想要时它就是 0。

**真正该看的储蓄率在 `trend` 里**，那个是按收入算的。两栏口径不同，别混。

**Q6. 固定支出占比高，是不是说明我该少花点？**

不一定。这个指标说的是**结构刚性**，不是花钱多少。占比高意味着你的支出里「不管怎样都得付」的部分大，抗风险能力弱——一旦收入中断，能砍的余地很小。

对应的行动不是"少喝咖啡"，是**动结构**：换更低的房租、重谈贷款、取消不再用的订阅。这类决策一年做一次就够了，但效果远大于日常省小钱。

**Q7. 日支出波动大就一定有问题吗？**

不。变异系数只在**有足够样本**时才有意义。如果你一周只记了 3 天，其中一天有大额支出，系数会很高，但那不是冲动消费，只是样本少。

它真正有用的地方是**横向对比**：同一个月里某几天异常高，去回忆那天发生了什么、用了什么支付方式。`references/pain-of-paying.md` 里提到，扫码、免密这类低痛感支付会系统性地推高单次消费额。

## 三、想改变但不知从哪下手

**Q8. 我存不下钱，是不是意志力太差？**

通常不是。这是个**决策架构问题**，`references/hyperbolic-discounting.md` 里的研究说得很清楚：Thaler 与 Benartzi 让参与者在**加薪之前**承诺把涨薪的一部分自动提高储蓄率，40 个月内储蓄率从 3.5% 提到 13.6%。对照组——被提供传统理财建议、随时可自行提高——几乎没变化。

差别不在自律，在于**要不要每次重新下决心**。所以 `plan` 给的方向永远是"设一个自动规则"，而不是"这个月多存 500"。

**Q9. 分类超支了，是不是该把预算调低？**

反过来。额度设得离现实太远，每次都超支，心理账户机制会**失效**——人会自动忽略一个总是报警的系统。

先看这个分类的超支是**一次性的**还是**持续的**。一次性（朋友聚会、看病）不必调预算；持续三个月都超，说明你的真实需求就是比预算高，应该调高预算，然后从别的分类里找空间，或者接受储蓄率目标下修。

**Q10. 有负债，是该先还债还是先存钱、先投资？**

**先存 1 个月应急金，再全力还高息债，还清后补到 3–6 个月。** 完全不存应急金就去还债，遇到意外只能再借，债会越滚越多。

「还债 vs 投资」是道算术题：18% 的信用卡利率意味着**少付利息就是确定性赚 18%**，优于任何风险资产的概率性回报。这不是保守，是算术。具体见 `references/compound-interest.md` 与 `references/debt-snowball-avalanche.md`。

**Q11. 收入涨了，怎么防止消费跟着涨？**

两件事：

1. **目标用百分比，不用绝对金额**。百分比随收入自动缩放，天然抵抗生活方式膨胀；绝对金额会被涨薪慢慢稀释。
2. **涨薪后先稳住消费水平半年**，让储蓄率吃掉涨幅。

原理在 `references/anchoring.md`（新收入成为新的锚）和 `references/hedonic-adaptation.md`（升级带来的愉悦会很快回到基线，但账单不会走）。

## 四、边界与误用

**Q12. 这个能告诉我该买什么基金/股票吗？**

不能，也不应该。本工具**不做投资建议、不推荐任何产品、不做税务与法律意见**。涉及资产配置、退休规划、税务处理，请咨询持牌顾问。

它能给你的是 FIRE 公式里那个关键输入：**年支出**。`trend` 里的「折算月支出」× 12 就是你的年支出基线，比任何估算都可靠，因为它是从你的真实记录折出来的。

**Q13. 我记了半年，数字从来没变过，是不是白记了？**

记账已经变成仪式性的自我安慰了。这时候该做的是跑 `plan`，然后**动一个结构性变量**——房租、订阅、发薪日自动转账，随便哪个。记录本身不是目的，改变才是。

**Q14. 数据存在哪？会不会上传？**

写在 `--data` 指定的本地目录：`events.jsonl`（每行一条 JSON，纯文本，可自己写脚本分析、可 git 版本管理）、`profile.json`、`reports/`。引擎**不联网、不上传**。

**Q15. 一笔钱记错了怎么办？**

用同一个 `--id` 重记一次，覆盖，不重复计数：

```bash
python scripts/budget.py --data ./my_money log \
  --date 2026-08-28 --kind out --amount 650 --category 娱乐 --id 2026-08-28#1
```

不指定 `--id` 时引擎按 `日期#序号` 自动生成（如 `2026-08-28#1`），`log` 命令的输出里能看到。

**Q16. 为什么 `--data` 要放在子命令前面？**

`--data` 是顶层参数，不是子命令的参数。

```bash
python scripts/budget.py --data ./my_money trend --days 30   # 对
python scripts/budget.py trend --days 30 --data ./my_money   # 会报错
```

# 自评（TRACE 五维）

包：self-budget-agent v2.0.0
自评日期：2026-09-01

## T — 理论基础（5.0/5）

13 篇 `references/` 长文，每篇带年份 + 期刊/书名出处，覆盖两条主线：

- **结构主线**：50/30/20（Warren & Tyagi 2005）、应急金（美联储 2019）、储蓄率与财务独立（Bengen 1994；Trinity Study 1998）、复利（Malkiel 1973）、债务雪球与雪崩（Ramsey 2003；Kellogg 2020）、FIRE（Domínguez & Robin 1992）。
- **行为主线**：心理账户（Thaler 1985）、双曲贴现与 Save More Tomorrow（Laibson 1997；Thaler & Benartzi 2004）、支付痛感（Prelec & Loewenstein 1998；Feinberg 1986）、沉没成本（Arkes & Blumer 1985）、锚定效应（Tversky & Kahneman 1974）、享乐适应（Brickman & Campbell 1971）、记账与自我监控（Harkin et al. 2016 元分析）。

不是"理财博主经验"的堆砌。每个引擎指标都能追到具体文献：`resources/money-models.json` 里逐项登记了算法定义与出处。设计与 sleep、fitness 包同源。

## R — 可重跑（5.0/5）

纯 Python 标准库，零第三方依赖，Python 3.8+。确定性计算：同一份 `events.jsonl` + `profile.json`，任何时间、任何机器重跑，输出完全一致。

`append_event` 按 `type+id` 幂等覆盖，修正错账不会重复计数——这是"可重跑"在记账场景下的关键保证，否则改一笔账整个月的统计就废了。

冒烟测试 `smoke_self_budget.py` **75 项全部 PASS**，覆盖：空库守卫、正常记录、四类参数校验（缺 amount / 金额为负 / 预算格式错 / 未知子命令）、健康数据集（risk 与 report 均 rc=0、报告落盘）、透支数据集（risk 与 report 均 rc=1）、幂等覆盖、版本一致性。

其中两项是**针对开发过程中修掉的真 bug 的回归**：预算分类不在 top5 时仍能取到实际金额；`plan` 的行动与提示同源。

## A — 可执行（5.0/5）

7 个子命令覆盖完整闭环：`set` 建档案 → `log` 记录 → `trend` 看全景 → `budget` 对预算 → `risk` 扫风险 → `plan` 取行动 → `report` 出报告。

每次只给**一个**行动（`plan`），且行动与提示的问题同源——v2.0.0 修掉了早期版本"按另一条优先级链选行动"导致的自相矛盾输出。

退出码文档化：`0` 正常 / `1` 存在中或高严重度弱项（agent 可直接据此判断是否介入）/ `2` 用法错误 / `4` 参数或数据不可用。与 self 系列其余包一致。

## C — 可复核（5.0/5）

留三类实物证据：

1. `events.jsonl` — 每行一条 JSON，纯文本，可人工查看、可自己写脚本分析、可 git 版本管理；
2. `profile.json` — 你的目标与应急金设定，改了什么一目了然；
3. `reports/budget-<日期>.md` — 每月一份报告落盘，两份并排看变化。

所有指标的计算口径写在 `resources/budget-domains.json` 里，不是黑盒。「必需」与「想要」分类集合互斥并在代码里加了断言，避免出现占比加总超过 100% 的假数据。

## E — 教育性（5.0/5）

不只是报数，每条弱项都配一条**具体行动**，且行动背后有理论支撑：

- "储蓄率低" → 不是"多存点"，而是"设发薪日自动转出"（Save More Tomorrow）；
- "冲动消费" → 不是"忍住"，而是"先连续记 30 天不做判断"（自我监控研究）；
- "固定支出高" → 不是"少花点"，而是"逐项过一遍：换房租、重谈贷款、取消订阅"（50/30/20 的结构诊断逻辑）；
- "订阅不想续又懒得取消" → 给判断标准（"如果今天从零开始我还会花这个钱吗"），而不是道德劝说。

`FAQ.md` 按"你会怎么问"组织，16 问覆盖从"坚持不下来"到"该买什么基金"的真实疑问。

## 已知短板（诚实记录）

1. **不追踪负债明细**。引擎不记录每笔债的利率与余额，所以无法直接做"还债顺序"的排序。变通做法是把每笔还款记为独立分类，但利率排序仍需用户自己做（`references/debt-snowball-avalanche.md` 给了方法）。
2. **不追踪资产与投资**。只做现金流记录，不算净资产。想看全貌需要别的东西配合。
3. **日支出波动只统计有支出的日子**。财务场景下这是对的（不记账的日子不代表没花钱，不能假设为 0），但样本少时指标不可靠，已在输出里显示"有支出的 N 天"提示样本量。
4. **储蓄率受窗口影响大**。收入季度性波动的人（年终奖、佣金制）用 30 天窗口会失真，需要手动加大 `--days`。引擎不自动识别这一点。

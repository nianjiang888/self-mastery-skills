# 复现方法学：把"它有时候崩"变成精确事实

调试的第一铁律是：**复现不了，就不算 bug，更不许修**。一个无法稳定复现的问题，你改了也证明不了改对，只会制造新的不确定性。本文件讲清楚"复现"这件事的工程方法——它远比"再点一次"严肃。

## 一、为什么复现这么难，又这么关键

bug 难复现，通常因为失败依赖于你没意识到的维度：输入数据、环境变量、时间戳、并发时序、资源水位、依赖版本。人类的直觉会本能地忽略这些"背景"，只盯着"我点了什么"。结果就是经典的"在我机器上是好的"。

而复现之所以是调试的第一性动作，是因为它一次性解决了三件事：

1. **确认 bug 真实存在**（不是误报、不是手滑）；
2. **提供可观测的失败事实**（错误类型、失败行），让后续假设有锚点；
3. **提供验证闭环的终点**——修了之后，用同一个复现确认它消失了。

self-debug-agent 的 `--reproduce` 就是把"模糊报错"萃取成**最小失败事实**：错误类型、错误消息、失败行号、该行源码。这一步做扎实，后面 `--classify` 和 `localize.py` 才有干净的输入。

## 二、最小复现（Minimal Reproducible Example）

目标不是"复现整个系统"，而是找到**仍能触发失败的最小输入 + 最小代码路径**。方法：

1. **删**。从能触发失败的完整场景出发，逐段删掉无关代码/无关输入，每删一次都跑一遍，只要失败还在，就说明删掉的部分与 bug 无关。这其实就是 Zeller Delta Debugging 的思想——系统性缩小到最小诱因。
2. **隔离**。把可疑逻辑抽成一个独立函数/脚本，脱离框架、脱离网络、脱离数据库，纯内存跑。能脱离后复现的 bug，定位成本骤降。
3. **固化**。把触发条件写成一个**确定的输入**（固定值，不依赖随机/时间/外部），这就是回归测试的雏形——你其实已经在为 `--regress` 准备素材了。

反面教材：拿着"生产环境偶发"去调，永远调不出来。正确做法是先把生产现象**翻译**成本地可重复的确定性用例，再动手。

## 三、环境钉固（Pinning the Environment）

很多"在我机器上好的"源于环境漂移。复现时要把环境维度钉死：

- **依赖版本**：锁 `requirements.txt` / `package-lock.json` / `go.mod`，记录精确版本。同一条代码在不同版本依赖下行为可不同。
- **语言/运行时版本**：Python 3.11 vs 3.12、Node 18 vs 20，语义可能有差。
- **配置与特性开关**：功能开关（feature flag）、环境变量、配置文件，全部记录。
- **数据快照**：用一份固定的小数据集复现，而不是连生产库。

钉固的意义在于：复现 = 代码 + 输入 + 环境。三者任一漂移，复现就失效。self-debug-agent 不替你管环境，但它的纪律会逼问你——"同样的输入在同样的依赖下，还能复现吗？"答不上来，就别进治愈循环。

## 四、flaky（偶发）bug 的隔离

偶发 bug 是最折磨人的：十次里挂一次。方法：

1. **提高采样**：把触发动作循环跑 N 次（如 100 次），统计失败率，确认它不是"这次正好没挂"。
2. **找区分维度**：对比成功与失败两次运行的差异——时间戳？线程调度？缓存命中？随机数种子？资源水位？把"偶发"变成"在某条件下必现"。
3. **注入确定性**：一旦怀疑某个维度（如并发时序），用可控方式制造该条件（固定调度、构造竞争窗口），把 flaky 变成稳定复现。
4. **别用 flaky 当断言**：这是红线。生成的回归测试必须是确定性的（固定输入→固定期望），禁止用随机、时间、网络当断言，否则测试本身就在制造噪声。

2025 年 Self-Debugging 复盘论文特别点出 **in-execution vs post-execution**：事后看输出对不对（post-execution）容易被"自生成测试的偏差"误导；而分析**执行中间状态**（in-execution）更能暴露逻辑偏差。对 flaky bug 尤其如此——看中间状态比看最终输出更能抓到那一次"恰好错了"的路径。

## 五、复现文档该长什么样

每次复现，建议沉淀成一条结构化记录（self-debug-agent 的 `--reproduce` 输出就是雏形）：

```
错误类型 : ZeroDivisionError
错误消息 : division by zero
失败行号 : 42
该行源码 : return total / count
复现步骤 : 调用 summarize([])（空列表）
最小输入 : count=0
环境     : Python 3.12, 依赖见 requirements.txt
```

这条记录同时是三样东西的原材料：

- `--classify` 的归类输入；
- `localize.py` 若配合覆盖率，定位的输入；
- `--regress` 的回归测试描述（"空列表时除零" → 一条钉死该行为的测试）。

## 六、常见复现陷阱

- **只复现了现象，没复现条件**：你"再点一次好了"，但没记录当时是什么条件，等于没复现。
- **在复现里顺手改了代码**：复现阶段严禁改代码，否则你分不清是"复现成功"还是"顺手修好了"。
- **用生产数据复现且数据在变**：用一份固定快照，别每次拉最新生产数据。
- **忽略时间维度**：定时任务、超时、缓存过期类 bug，必须考虑"跑了多久""几点触发的"。

记住 self-debug-agent 的纪律：**拿不出最小复现的修复，一律视为安慰剂。** 先把"为什么挂了"用事实钉死，再谈怎么修。

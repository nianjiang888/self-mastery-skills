# 常见问题（FAQ）

## 它和普通的报错阅读器有什么不同？

普通工具只把 traceback 打印出来给你看。self-debug-agent 做四件额外的事：① 把报错**萃取成最小失败事实**（错误类型/失败行/源码）；② 用探针把 bug **归类**到六类并给根因与修法方向；③ 用 SBFL 给每行算**可疑度**排出病灶；④ 治愈后**自动把 bug 落成永久回归测试**。它是一台闭环引擎，不是阅读器。

## 脚本真的会帮我改代码吗？

不会，也不该。脚本是**纪律引擎**：它负责复现萃取、归类探针、SBFL 计算、治愈循环记账、回归测试脚手架生成与校验。真正写补丁的是你或你的编程 Agent。分工和 self-evaluate-agent 一致——引擎管闭环，人/模型管产出。这样既不越权，又保证过程不糊弄。

## 为什么"复现不了就不许修"？

因为拿不出最小复现的"修复"无法被证明是对的，它和没修一样，甚至更糟（制造了新的不确定性）。脚本遇到无错误类型的 trace 会拒绝进入治愈循环（退出码 2），把这条纪律焊死。

## 归类探针说"未命中任何已知签名"怎么办？

这说明 bug 可能不在代码逻辑里（环境/数据），或属于罕见类型。脚本会把它列为"待验证假设"并给排查方向，而不是瞎猜。此时建议用 `--reproduce` 拿到的失败行逐行读执行语义，或检查环境/数据。

## SBFL 排第一的行就一定是病根吗？

不是。SBFL 是**排序**不是**定罪**，可疑度高的行要人工确认。它的价值是把"感觉是这儿"变成"数据说最可能是这儿"，帮你把注意力收敛到少数几行，而不是全文件乱改。

## 治愈循环跑了很多轮还没收敛？

脚本会为每轮记账（heal_log.jsonl），轮数到上限（默认 5）仍未收敛时，你应当**如实报告卡在哪一类的哪一行假设**，而不是编一个"已修复"。过度自信是调试最大的敌人——Self-Debugging 论文也证明，执行反馈正是用来压住这种过度自信的。

## "自我"到底指什么？

指**自主**：模型不依赖人类监督、也不依赖更强模型引导，自己调试自己写的程序（见 2025 年 Self-Debugging 复盘论文的定义）。再加上"每个 bug 自动变成永久回归测试"的免疫能力，就叫"自我"——不假外求，且越调越稳。

## 这个包和 self-improvement-agent 啥关系？

self-improvement 把错误变成抽象永久记忆；self-debug 把错误变成**具体、可重跑**的回归测试，是前者在工程上的硬落地。两者同源，配合使用效果最好。

## 生成的回归测试能直接跑吗？

`--regress` 给的是**脚手架**（已含命名、bug 描述、输入、期望），你需补完 `result == expected` 那一行并落到正式测试套件。脚本会主动拒绝含随机/时间/网络等脆弱特征的条目，保证确定性。

# self-reflect-agent 理论根基

本引擎不靠「你该多反省」这种空话驱动，而是把六条经实证的研究传统，落成可重跑的代码逻辑。本文说明每一条理论落在引擎的哪个位置，以及它们如何串成一条从「单环」到「双环」的升级路径。

## 一、Schön 反思实践（1983）：两种反思

Donald Schön 在《The Reflective Practitioner》里区分了两种反思：

- **反思于行动之后（reflection-on-action）**：事情结束后回头看，我当时依据什么假设做了那个决定。这是 most people 唯一会做的反思。
- **行动中的反思（reflection-in-action）**：在反应发生的「那一刻」就调整自己。这是专家与新手的分水岭。

引擎的 `log` 落的是 reflection-on-action 的原材料；而 `pattern` / `blindspot` 发现的反复惯性，正是通往 reflection-in-action 的训练场——只有先看清「我总在哪儿卡住」，才可能在卡住的下一秒就换反应。

## 二、Argyris 单环 / 双环学习（1974/1978）：本引擎的脊柱

Chris Argyris 与 Schön 进一步提出：

- **单环学习（single-loop）**：在既有目标与规则内修正行为。「下次忍住别发火」就是典型的单环——目标没变，只是要求自己执行得更好。
- **双环学习（double-loop）**：质疑目标与前提本身。「我为什么把『被质疑』自动解读成『被攻击』，以至于必须发火？」这才是改根因。

绝大多数「反省」停在单环，所以同样的坑反复跳。引擎的设计故意把双环往前推：

- `pattern` 检测到破坏性惯性时，提示「需要追问『我为什么总这样』而非『下次怎么忍住』」；
- `blindspot` 一旦命中言行系统性背离，退出码直接给 **4（双环警报）**，逼你把注意力从「改行为」挪到「改前提」。

## 三、美国陆军 AAR 四问（1970s）：复盘的结构

After-Action Review 用四个问题把模糊的「感想」变成可执行的改进：

1. 本该发生什么（暴露你的预期与隐含前提）；
2. 实际发生了什么（只陈述可观察事实）；
3. 为什么有差异（根因）；
4. 下次怎么改（具体、可验证的小行动）。

引擎 `aar` 子命令直接生成这四问模板，并刻意在第 3 问标注「双环」，防止复盘滑回单环。

## 四、Gibbs 反思循环（1988）与 Kolb 经验学习（1984）

Gibbs 把反思拆成六阶段（描述→感受→评价→分析→结论→行动），Kolb 则强调「具体经验→反思观察→抽象概念→主动实验」的闭环。两者共同说明：反思不是一次性情绪宣泄，而是「经验 → 提炼 → 再实践」的循环。引擎的 `report` 周期报告，就是把零散的 `log` 条目重新聚合成这个循环的输入。

## 五、Dweck 成长型思维（2006）：重写自我叙事

Carol Dweck 证明，把「我做不到 X」改写成「我暂时还没掌握 X」，会显著改变后续坚持度。引擎在 `resources/reflect-prompts.json` 的 `dweck_mindset` 中内置这条改写提示，供 `blindspot` 命中时调用，把「我又失败了」转成「下一步可练的是……」。

## 六、Flavell 元认知（1979）与 Brookfield 四透镜（1998）

Flavell 提出「对认知的认知」——知道自己是怎么想的，比想出答案更重要。Brookfield 给出四个审视自己的透镜（自己 / 他人 / 理论 / 现实）。引擎的 `blindspot` 本质上就是 Brookfield 的「现实透镜 vs 自己透镜」的自动化：把「你自称的自己」和「日志证据里的自己」并排放，差异即盲点。

## 串起来：一条升级路径

```
log（沉淀经验）
  → pattern（看见惯性：这是单环的尽头）
  → aar（四问复盘，刻意逼出双环）
  → claim + blindspot（言行对照，系统性背离触发双环警报 4）
  → report（周期聚合，喂养下一轮循环）
```

理论不是装饰。每一条都对应一个子命令、一种退出码、一份可重跑的产物——这就是「日三省」从格言变成机制的方式。
